# 候见 · 惊蛰 WebAR 原型

《候见》是一个面向“二十四节气文化作品设计”赛道的可运行 WebAR 原型。第一阶段只实现“惊蛰卡”的完整体验闭环：识别卡片、让大地升温、触发春雷、解锁惊蛰三候、记录现实观察并生成个人惊蛰签。

## 直接运行

项目没有第三方运行依赖。需要 Node.js 18+：

```bash
npm run dev
```

在电脑浏览器打开 `http://localhost:4173`。localhost 可直接请求摄像头权限。

手机真机测试必须使用 HTTPS 部署地址；把整个项目的构建产物部署到任意 HTTPS 静态网站即可：

```bash
npm run build
```

构建产物位于 `dist/`。

## 使用方式

1. 打印或在另一块屏幕打开 `assets/jingzhe-card.svg`。
2. 点击“开始观候”，允许浏览器使用摄像头。
3. 让卡片的青、品红、绿、黄四个角标完整进入镜头。
4. 按屏幕提示完成升温、春雷、三候和观察记录。
5. 没有卡片时可以使用首页的“演示模式”。

## 追踪原理

第一版使用零依赖的四色角标追踪器。网页在本机低分辨率分析摄像头帧，定位四个色标的中心，估算卡片中心、尺寸和旋转角度，再把程序生成的 2.5D 物候场景叠加到卡面。摄像头画面不会上传。

这个方案优先保证比赛演示的稳定性和可离线维护性。后续可以保持页面、交互和数据结构不变，只替换 `trackMarker()` 为 MindAR 等更完整的平面图像追踪实现。

## 兼容性与测试建议

- iOS Safari、Android Chrome：使用 HTTPS。
- 微信内置浏览器：需要单独测试摄像头权限；若失败，提示用户在系统浏览器打开。
- 避免打印反光，建议使用哑光纸。
- 建议卡片至少 A5 大小，体验距离约 30 厘米。
- 弱光或彩色灯光会降低色标识别率。

## 主要文件

- `index.html`：四个核心页面。
- `styles.css`：移动端视觉与响应式布局。
- `app.js`：摄像头、卡片追踪、AR绘制和交互状态。
- `data/solar-terms.js`：24节气扩展数据结构。
- `assets/jingzhe-card.svg`：A5可打印惊蛰卡。
- `docs/acceptance-checklist.md`：真机验收清单。
